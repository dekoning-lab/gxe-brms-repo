# Data: schema, sources, and synthetic dataset

This document describes the input data file that the pipeline expects,
the variables it uses, and the synthetic dataset shipped with the
repository for demonstration purposes.

## Access to the real APrON dataset

The Alberta Pregnancy Outcomes and Nutrition (APrON) cohort dataset
contains identifiable maternal–infant dyad information and is **not
redistributable** under the cohort's REB constraints. Researchers
with appropriate IRB/REB approval can request data access from the
APrON Study Team. See
[https://www.apronstudy.ca/](https://www.apronstudy.ca/) and the
paper's data-availability statement for the current procedure.

## Synthetic dataset

A synthetic dataset matching the schema below is shipped at
`data/synthetic/Fulldata_synthetic.txt`. It is generated by
`scripts/synthetic/00_generate_synthetic_data.py` from the real
file's marginal distributions and missingness pattern. Synthetic
records use IDs `DUMMY-NNNNN` (no overlap with the real cohort) and
contain no individual-level information from any real participant.
Any results computed on the synthetic dataset are **not
scientifically meaningful** — its sole purpose is to demonstrate that
the pipeline runs end-to-end and to provide a working example for
adapting the code to other cohorts.

## Expected file location

The pipeline reads its input from:

```
data/Fulldata_with_PCs_and_maternal_PCs.txt
```

Tab-delimited, UTF-8, header row, missing values as empty strings or
the literal `NA`. To use the synthetic dataset for a smoke test:

```bash
cp data/synthetic/Fulldata_synthetic.txt data/Fulldata_with_PCs_and_maternal_PCs.txt
```

## Variable codebook

The input file contains 112 columns. The pipeline reads a subset for
imputation and modelling. The full column list, in order, is
documented in `data/SCHEMA.csv` (one row per column with
type / description / source). The analysis-relevant subset:

### Identifiers

| Column | Type | Description |
|---|---|---|
| `Samples` | string | Participant ID (`AP-NNNNN` in real data; `DUMMY-NNNNN` in synthetic) |
| `Inf_APrONID` | string | Internal cohort infant identifier |
| `MaternalID` | string | Internal cohort maternal identifier |

### Outcome and demographics

| Column | Type | Range / coding | Description |
|---|---|---|---|
| `Final7PointLikertScale` | integer | 1–7 (NA allowed) | 7-point ordinal attachment classification |
| `Sex` | integer | 0 = Female, 1 = Male | Infant sex (APrON codebook) |
| `infant_age` | numeric | months | Age at attachment assessment |
| `ethnicity` | integer | category code | Coarse ethnicity grouping |

### Parenting variables (CARE-Index, 6-month dyadic assessment)

| Column | Type | Description |
|---|---|---|
| `sens` | numeric | Caregiver **sensitivity** (CARE-Index) |
| `cont` | numeric | Caregiver **controlling** behaviour (CARE-Index) |
| `unre` | numeric | Caregiver **unresponsiveness** (CARE-Index) |
| `pass` | numeric | Child **passivity** sub-scale |
| `diff` | numeric | Child **difficultness** sub-scale |

Each "parenting model" in the paper uses one of `{sens, cont, unre}` as
its primary parenting variable; `pass` and `diff` are included as
child-behaviour covariates in all M4 models (see Phase 3 of the
pipeline).

### Genetic variants (coded as additive or dominant/recessive integers)

| Column | Coding | Plasticity allele |
|---|---|---|
| `DRD2`         | 0/1 dominant   | A1 (T) |
| `BDNF`         | 0/1 dominant   | Met (T) |
| `CNR1-77`      | 0/1 dominant   | A |
| `CNR1-10`      | 0/1 recessive  | A (AA = 1) |
| `DRD4`         | 0/1 dominant   | 7-repeat carrier |
| `MAOA`         | 0/1 X-linked   | Low-activity (2/3/5-repeat); males hemizygous |
| `SLC6A3-9R`    | 0/1 dominant   | 9-repeat carrier |
| `SLC6A3-10R`   | 0/1 recessive  | 10-repeat/10-repeat = 1 |
| `5HTTLPR`      | 0/1/2 additive | S allele count (Letourneau 2019 biallelic coding); the alt-coding pipeline uses the Hu et al. (2006) functional triallelic coding |

See Table 4 of the manuscript for the full biological rationale.

### Ancestry principal components

| Column | Description |
|---|---|
| `PC1`–`PC3`             | Infant ancestry PCs (in the analysis) |
| `PC4`–`PC50`            | Additional infant PCs (not used; provided for completeness) |
| `maternal_PC1`–`maternal_PC3` | Maternal ancestry PCs (auxiliary imputation variables) |

### Other columns

Additional CBCL behaviour scales (raw and T-scores) are present in the
file but are not used by the analysis pipeline. They are preserved in
the synthetic dataset to maintain schema parity.

## Adapting to other cohorts

If you have data with similar structure but different column names,
the simplest path is:

1. Rename your columns to match the schema above.
2. Ensure missing values are blank or `NA` (not -9, -999, etc.).
3. Place the resulting tab-delimited file at
   `data/Fulldata_with_PCs_and_maternal_PCs.txt`.
4. Run the pipeline (see `docs/pipeline.md`).

The MICE step adapts to the missingness pattern in your data
automatically. The brms model formulas assume the listed genetic
variants are present; if your cohort has a different set of variants,
edit the `genes` vector in `scripts/52_fit_m4_v3.R` (line ~80) and
the prior block accordingly.
